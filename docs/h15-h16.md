# Validation and recovery notes

## Pinned behavior

- Mainnet H15: DAA 140,115,000; H16: DAA 147,000,000.
- Testnet H15: DAA 3,500; H16: DAA 180,000.
- H15 PoM v5 verification and H16 pad sizing come from the pinned official Rust implementation, not from miner-reported prefix values.
- Service strikes come from `GetServiceStrikes` (wire fields 1120/1121). Current requests and audit draws come from `GetAwaitedOpenings` (1126/1127).
- Audit enumeration requires explicit response transaction IDs. The bridge queries every response retained in its state, including responses whose requests have closed. An escrow-key query alone cannot discover every historical response audit after state loss.
- A request uses its computed transaction ID, not a prefix of its payload. Ownership, model, token commitment, signed response, audit draw/seed, path, parent-phase root and deadline are checked before publication.
- `verifier/src/audit.rs` adapts the private opening-check functions from the pinned node's `consensus/core/src/collateral.rs`. Public cryptographic verification still uses that pinned node's verifiable-inference crate. Review this adapter when changing the pin.

## Observed validation boundary

Validated on 2026-11-11 with dedicated test-only keys and the official miner/node release assets. Both final runs used the same clean runtime source, `1a06691a83d7e4c770fbe28196e32d99800f60b8`, and the same race-instrumented bridge binary.

Final runtime-code checks: Windows Go build PASS, Go vet PASS, 39 Go test functions PASS with race detection and zero failures; the inherited manual third-party-pool snooper is SKIP. Eight Rust tests passed on the unchanged verifier. Earlier checks on unchanged dependencies/verifier also passed: govulncheck v1.9.0, locked Cargo check, Clippy with warnings denied, release build and five native verifier protocol checks. Each final trial passed 80 loopback authentication, frame-limit and status checks (eight distinct checks repeated ten times). Docker and Linux builds were not run.

The final H15 trial independently re-read and header-hash checked 1,049 distinct node-accepted blocks at DAA 10,908–11,941 on a private isolated testnet-10 chain. The official rules were unchanged: the chain reached the H15 threshold of 3,500 naturally and stayed below H16 at 180,000. The final H16 trial checked 938 blocks at DAA 547,370–548,295 on public testnet-10. Both used Gemma-4-12B on RTX 5080, official miner v0.6.1-PoM and node v1.6.7-PoM.

Each final trial executed a fresh paid private request, a signed response independently verified and decrypted by the requester, and three opening transactions accepted by the selected chain. Request/response acceptance and all opening IDs were checked against the node's fully paginated accepted-transaction results. No opening was currently owed at the final observation; consecutive/lifetime strikes and pending burns were zero. Complete logs contained no race/panic after process cleanup. See the [full-cycle test record](validation/h15-h16-inference-20261111.md). Accepted DAG blocks are not all necessarily selected-chain reward blocks.

The earlier [H16 mining-only record](validation/h16-testnet-20261111.md) is retained as history, including the disconnect regression; its counts are not added to the final runs above. A separate [official-miner TLS run](validation/stratum-tls-20261111.md) confirmed another 78 blocks over direct TLS 1.3 (`stratum+ssl://` and `stratum+tls://`), certificate refusals and 24 supplemental checks; it did not submit another inference request.

The runtime checks exposed and fixed an ignored legacy challenge that prevented job admission, rejection of network-valid blocks above a harder pool share target, a nil legacy escrow-store call, unsynced zero-strike reporting, and listener/test-socket shutdown races. Repeated identical model declarations are acknowledged; changing the declared model set remains forbidden within a session.

Real inference subsequently exposed three more defects, each reproduced by a regression before correction: missing response IDs in audit queries, distinct `null`/`[]` encodings of the empty attention root path, and transient readiness loss incorrectly returning fatal Unauthorized rather than retryable Busy. Retained attention roots and pending opening digests are migrated without discarding commitments; contradictory roots stop recovery. Busy still refuses the share while the readiness gate is closed.

The scan is limited to known Go vulnerability records and reachable Go calls. It does not audit the Rust dependency graph, inherited C code, operating system or deployment. It is not a security certification.

These runs cover bounded mining/inference/mining transitions and the actual draws of two short requests. A retained trace was also resumed during diagnosis; this does not qualify general recovery. Other models/hardware, every attention phase, historical mainnet transitions, general node outage/restart/reorg recovery, queue pressure, pool-scale performance, remote TLS deployment, mainnet rewards and escrow recovery remain unqualified. The [TLS note](stratum-tls.md) records transport checks separately. The testnet passes are bounded compatibility evidence for code review, not complete deployment qualification.

## Failure and recovery

The state file contains encrypted request payloads and signed publications, not decrypted prompts or worker tokens. Protect it because it binds a response to the worker retaining its trace. A helper timeout or broken pipe closes verification; an operator restart is required. The bridge never switches to prefix-only proof acceptance.

RPCs have request deadlines, and signed publication retries reuse exactly the persisted envelope. Mempool admission is not chain acceptance. Node obligations decide which requests may be served and which opening pieces remain owed. An absent, failed or stale node observation is never replaced by a zero-strike claim.

The chain scan retains up to 8,192 selected-chain draw candidates and walks at most 2,048 blocks to reconcile a checkpoint. Initial startup samples 128 selected-chain blocks and their blue merge blocks. This initial bounded backfill is not a general recovery of historical service obligations. Use a fresh dedicated key, or reconcile existing obligations and retain the previous state/worker traces before migration. A returned audit with no retained owner/seed, or a checkpoint outside the scan limit, blocks new mining work instead of manufacturing state. Because the node only enumerates audits for supplied response IDs, this gate cannot detect every obligation whose response ID was lost with the state file.

There are at most 1,024 retained tasks and 128 configured worker identities. File/line, proof, helper reply and audit bundle sizes are bounded. Capacity exhaustion requires reconciliation; it does not discard an owed audit. Worker assignment before a prepared response may be retried or reassigned; after preparation it stays with the authenticated worker identity retaining that response's trace. Tokens and worker identities must not be shared between independent machines.

Configuration is for one payout identity. A public multi-account pool needs separately designed ownership, accounting, isolated signing, admission, privacy, payments and monitoring policies. Third-party pool policies and payments are outside this update.
